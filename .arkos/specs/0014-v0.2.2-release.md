# SPEC-0014: ARK OS v0.2.2 release

GitHub issue: [#27](https://github.com/ark360-hq/arkos/issues/27).

## Problem

`main` carries four approved specs of work that adopters cannot obtain from a tagged release: SPEC-0010 (roadmap and CONTRIBUTING tidy, #16), SPEC-0011 (brand rename to ARK OS, #17), SPEC-0012 (Intelligence module extract at `modules/intelligence/`, #20 and #21), and SPEC-0013 (product AI build-gate scan, #22). The latest GitHub Release is still v0.2.1 (2026-10-09), and `CHANGELOG.md` lists all of this under `[Unreleased]`.

Published version labels (`AGENTS.md`, `.arkos/arkos.yml`, `README.md`, `QUICKSTART.md`, `SECURITY.md`, `.arkos/proof-sheet.md`, `docs/standards.md`, `docs/framework.md`) all say 0.2.1, so an adopter cloning `main` cannot tell which framework version governs them. James Park decided on 2026-10-17 to ship this as v0.2.2 and to keep the v0.3 label for the Microsoft agentic module.

## Out of scope

1. Merging this change. The owner merges after CI is green.
2. Any change to `modules/intelligence/`, `.arkos/scripts/`, `.github/workflows/`, ADRs, contracts, or threat models. This release ships what is already on `main`.
3. The v0.3 Microsoft agentic module (#26) and the later roadmap items (#28).
4. Rewriting historical `[0.2.1]` or `[0.1.0]` CHANGELOG sections, or historical specs and ADRs.
5. Implementing `npx create-arkos`, `npx arkos upgrade`, or `npx arkos proof`.

## Requirements

### Ubiquitous (always true, no trigger)

> REQ-001: The current framework version label shall be `0.2.2` in `.arkos/arkos.yml` (`arkos-version`), `AGENTS.md`, `.arkos/proof-sheet.md`, `docs/standards.md` (binding statement and "Out of scope" heading), `docs/framework.md` (document version line, current-governance statements, and roadmap "Released" line), `README.md`, `QUICKSTART.md`, and `SECURITY.md`.

> REQ-002: `CHANGELOG.md` shall move every entry currently under `[Unreleased]` to a new `## [0.2.2] - 2026-10-17` section, keep an empty `## [Unreleased]` section above it, and provide Keep a Changelog compare links for `[Unreleased]` (`v0.2.2...HEAD`) and `[0.2.2]` (`v0.2.1...v0.2.2`).

> REQ-003: The `[0.2.2]` section shall record this spec and the version-label change, each referencing SPEC-0014.

### Event-driven (triggered by an event)

> REQ-004: WHEN the pull request merges, the owner shall create git tag `v0.2.2` on the merge commit and publish a GitHub Release titled `ARK OS v0.2.2` whose notes are the `[0.2.2]` CHANGELOG section.

### Unwanted behaviour (what must not happen)

> REQ-005: IF this change is applied THEN it shall NOT modify any file outside `CHANGELOG.md`, `.arkos/specs/0014-v0.2.2-release.md`, and the version-label files named in REQ-001.
