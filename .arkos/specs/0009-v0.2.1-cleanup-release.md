# SPEC-0009: ArkOS v0.2.1 cleanup release

## Problem

The repository is ready for a cleanup release, but published labels and artefacts are inconsistent and would mislead an adopter or a GitHub licence scanner:

1. `.arkos/arkos.yml` declares `arkos-version: "0.2"`, while `AGENTS.md`, `.arkos/proof-sheet.md`, `docs/standards.md`, and other current-version labels still say v0.1.
2. `LICENSE` is a modified Apache text (rewritten section 4 and a filled-in copyright block). GitHub therefore does not detect Apache-2.0.
3. `docs/framework.md` and related docs present `npx create-arkos` and `npx arkos upgrade` as if they exist. Neither package is published.
4. `CHANGELOG.md` still lists the post-0.1.0 work under `[Unreleased]`. The `[0.1.0]` footer points at `releases/tag/v0.1.0`, a tag that was never created.

## Out of scope

1. Merging this change, creating git tag `v0.2.1`, or publishing a GitHub Release. The owner does that after approval.
2. Implementing `npx create-arkos`, `npx arkos upgrade`, or `npx arkos proof`.
3. Rewriting historical specs, ADRs, or the `[0.1.0]` CHANGELOG section as if they were always 0.2.1.
4. Changing ADR-0003. The licence decision is unchanged; only the licence file text is restored.

## Requirements

### Ubiquitous (always true, no trigger)

> REQ-001: The current framework version label shall be `0.2.1` in `.arkos/arkos.yml` (`arkos-version`), `AGENTS.md`, `.arkos/proof-sheet.md`, `docs/standards.md`, `docs/framework.md` (document version and current-governance statements), `README.md`, `QUICKSTART.md`, and `SECURITY.md`.

> REQ-002: `LICENSE` shall be the unmodified Apache License 2.0 text published at `https://www.apache.org/licenses/LICENSE-2.0.txt`. Copyright and attribution for ARK360 shall live in `NOTICE`, not in `LICENSE`.

> REQ-003: Documentation that mentions `npx create-arkos` or `npx arkos upgrade` shall mark those commands as planned and not available, and shall describe the current adoption path as GitHub "Use this template" (or clone of this repository).

> REQ-004: `CHANGELOG.md` shall move the post-0.1.0 Unreleased entries under `## [0.2.1] - 2026-10-16`, keep an empty `## [Unreleased]` section, and provide Keep a Changelog compare links for `[Unreleased]` (`v0.2.1...HEAD`) and `[0.2.1]`. The `[0.1.0]` footer shall not use the non-existent `v0.1.0` tag URL.

### Unwanted behaviour (what must not happen)

> REQ-005: IF a reader follows the documented adoption path THEN the system shall NOT instruct them to run `npx create-arkos` or `npx arkos upgrade` as a working command.
