# ARK OS v0.2 enhancement proposal: Claude Code extension layer

**Status:** Approved for implementation  
**Framework version:** 0.2  
**Date:** 2026-05-22

---

## Phase 1: Assessment

### What the repo already does well

- **Single source of truth:** `AGENTS.md` is an active-enforcer document (hard-stop block, pre-flight table, PRD/spec/branch/issue workflows). CI backstops via `.github/workflows/arkos.yml` and `.arkos/scripts/`.
- **Thin IDE adapters:** `CLAUDE.md`, `.cursor/rules/arkos.mdc`, and `.github/copilot-instructions.md` point to `AGENTS.md` without duplicating governance (ADR-0001).
- **Stack- and runtime-agnostic:** No framework lock-in in CI placeholders; adopters wire their own commands.
- **Afternoon adoption:** `QUICKSTART.md` and template placeholders let gates pass before real tooling is wired.
- **Claude baseline:** `CLAUDE.md` already imports `AGENTS.md` via `@AGENTS.md` and adds Claude-specific session notes.

### What is missing for stronger Claude Code support

| Gap | Impact |
|-----|--------|
| No `.claude/` scaffold | Teams cannot use Claude-native settings, rules, slash commands, or hooks without inventing structure |
| No settings layering guidance | Risk of committing personal MCP or permission overrides as team defaults |
| No repeatable workflows | Governance checks and spec scaffolding rely on prose in `AGENTS.md` only |
| No MCP example | No safe pattern for shared vs personal MCP configuration |
| Docs do not explain the three-layer model | `AGENTS.md` vs `CLAUDE.md` vs `.claude/*` is implicit |

### What must not change

- `AGENTS.md` remains authoritative for universal governance.
- Thin adapters stay thin; no large rule blocks in `CLAUDE.md` or `.claude/rules/*`.
- Five gates, `.arkos/constitution.md`, stack-agnostic CI, repo-native audit trail.
- Non-Claude IDEs remain first-class; no Cursor parity directory required in v0.2.
- Australian English; no em dashes in new prose (except verbatim `docs/framework.md` per SPEC-0001).

## Phase 2: Proposal

### Recommended scope (MVP)

Introduce an **optional Claude Code extension layer** that improves ergonomics without becoming a second constitution.

### Governance layers

| Content | Location |
|---------|----------|
| Universal governance, pre-flight, workflows | `AGENTS.md` |
| Claude session behaviour (Plan mode, compaction, imports) | `CLAUDE.md` |
| Team-shared Claude settings, hooks wiring | `.claude/settings.json` |
| Personal overrides | `.claude/settings.local.json` (gitignored; copy from example) |
| Claude-only modular helpers (still thin) | `.claude/rules/`, `.claude/commands/` |
| MCP team template (example only) | `.mcp.json.example` then copy to `.mcp.json` when ready |

Claude Code works with **only** `AGENTS.md` and `CLAUDE.md`. The `.claude/` directory is optional.

### Files added in v0.2

| File | Purpose |
|------|---------|
| `.arkos/specs/0005-claude-code-extension-layer.md` | Spec for this change |
| `.arkos/adr/0004-claude-code-extension-layer.md` | Structural ADR |
| `.gitignore` | Ignore local Claude and MCP overrides |
| `.claude/README.md` | Extension layer overview |
| `.claude/settings.json` | Shared defaults; hooks disabled by default |
| `.claude/settings.local.json.example` | Personal override pattern |
| `.claude/rules/arkos.md` | Thin pointer to `AGENTS.md` |
| `.claude/commands/governance-check.md` | `/governance-check` slash command |
| `.claude/commands/scaffold-spec.md` | `/scaffold-spec` slash command |
| `.claude/hooks/block-edit-on-main.sh` | Sample `PreToolUse` hook (opt-in) |
| `.claude/hooks/README.md` | Enable/disable hook instructions |
| `.mcp.json.example` | Example-only MCP template |

### Files modified in v0.2

- `.arkos/arkos.yml` (version 0.2, `claude-extension: true`)
- `README.md`, `QUICKSTART.md`, `CLAUDE.md`, `.cursor/rules/arkos.mdc`, `CHANGELOG.md`
- `docs/framework.md` (optional file tree entries)

### Files not added yet (v0.3+)

- `.claude/agents/`, `.claude/skills/`, `output-styles/`
- `npx create-arkos` / `npx arkos upgrade` CLI (planned, not available)
- Stack modules (`arkos-module-nextjs`, etc.)
- CI jobs that lint `.claude/` or require MCP servers
- Cursor/Windsurf parity directories
- Managed enterprise `managed-settings.json` templates

### Risks and trade-offs

| Risk | Mitigation |
|------|------------|
| Governance drift into `.claude/rules/` | Rules are pointers only; ADR-0004; max ~10 lines per rule file |
| Hook blocks legitimate `main` hotfixes | Hook off by default; use feature branches |
| `.mcp.json.example` implies working MCP | Explicit example-only header; opt-in copy |
| Template size creep | ~12 stub files; no runtime deps |
| ADR-0001 tension | ADR-0004 clarifies extension layer, not a second SSOT |
